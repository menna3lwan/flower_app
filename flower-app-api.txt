    REST API documentation for the Flower App ecosystem (User app, Driver app, Admin panel).
    Derived from the Figma design "Flower App" (Login, Sign up, Apply/Driver registration,
    Forget password flow, Vehicle selection).

    ## Response envelope
    Every endpoint in this API returns the same top-level envelope (see `BaseResponse` and
    its typed variants below), regardless of success or failure:

    ```json
    {
      "success": true,
      "code": 200,
      "message": "Request completed successfully",
      "data": {},
      "errors": null,
      "meta": null
    }
    ```

    - `success` — boolean, `true` for 2xx responses, `false` otherwise.
    - `code` — the HTTP status code, duplicated in the body for clients that only read the payload.
    - `message` — human readable, safe to show to the end user.
    - `data` — the endpoint-specific payload. `null` when there is nothing to return (e.g. a 204-style ack) or on error.
    - `errors` — `null` on success. On failure, an array of `{ field, message }` validation/business errors.
    - `meta` — `null` unless the endpoint is paginated (see `get vehicles list`).
